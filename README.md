# Світло поруч — графік відключень для Кіровоградської області

Це статичний сайт без сервера, бази даних, збірки та сторонніх JavaScript-бібліотек. Його можна розмістити на GitHub Pages.

## Що вже реалізовано

- Адаптивний інтерфейс для телефону, планшета й комп'ютера.
- Картки кількох адрес: населений пункт, вулиця, будинок, назва й підчерга; адресу можна змінити або видалити.
- Запам'ятовування адрес і вибраної картки в `localStorage` конкретного браузера. Обліковий запис не потрібний, адреси не надсилаються на сервер.
- Графік на сьогодні й завтра: 24 погодинні інтервали та стани «світло є», «світла немає», «можливе відключення», «немає даних».
- Світла й темна теми.
- Чесне відображення відсутніх даних: порожні значення не підміняються вигаданими годинами.
- GitHub Actions, який приблизно раз на 10 хвилин пробує завантажити публічну сторінку графіків Svitlo.live, перевіряє, що знайдено всі 12 підчерг для сьогодні та завтра, і записує дані в `data/schedule.json` тільки коли вони змінилися.

## Важливе обмеження адресного пошуку

Відкритий стабільний API, який надійно зіставляє будь-яку введену адресу з підчергою, не підтверджено. Тому користувач має один раз перевірити адресу на офіційному сайті оператора й вибрати підтверджену підчергу у формі сайту. Не вгадуйте підчергу: у різних адрес вона може відрізнятися.

Перевірка адреси та підчерги: <https://kiroe.com.ua/electricity-blackout>

Дані для побудови годинного графіка: <https://svitlo.live/kirovogradska-oblast>. Це зовнішній довідковий ресурс, а не офіційний оператор електромереж. Якщо графік критично важливий, звіряйте інформацію з оператором.

## Публікація на GitHub Pages

1. Увійдіть у GitHub і створіть **новий публічний репозиторій**. Наприклад, `svitlo-poruch`. Якщо це перший сайт на GitHub Pages, публічного репозиторію достатньо.
2. Розпакуйте архів на комп'ютері. Завантажте **вміст** папки `svitlo-krop` у корінь репозиторію, а не саму папку `svitlo-krop` усередину нього. У корені мають бути `index.html`, `app.js`, `styles.css`, `data/`, `scripts/` і `.github/`.
3. На вкладці репозиторію відкрийте **Settings → Pages**.
4. У секції **Build and deployment** виберіть **Deploy from a branch**. Для branch оберіть `main`, папку `/ (root)` і натисніть **Save**.
5. Зачекайте, доки GitHub Pages опублікує сайт. Посилання буде показано на сторінці **Settings → Pages**. Зазвичай адреса має вигляд `https://ВАШ_ЛОГІН.github.io/svitlo-poruch/`.
6. Перевірте сайт за посиланням. Додайте тестову адресу й виберіть правильну підчергу. Перезавантажте сторінку: картка адреси має залишитися.

> Якщо ви використовуєте іншу назву гілки, виберіть цю гілку замість `main`.

## Увімкнення автоматичного оновлення даних

Файл `.github/workflows/update-schedule.yml` запускається за розкладом приблизно кожні 10 хвилин. GitHub Actions використовує стандартний `GITHUB_TOKEN`; окремий секрет додавати не потрібно.

1. У репозиторії відкрийте **Settings → Actions → General**.
2. У секції **Workflow permissions** переконайтеся, що для workflow дозволені записи до репозиторію (read and write access). Це потрібно, щоб оновлювати `data/schedule.json`.
3. Відкрийте вкладку **Actions** і виберіть workflow **Refresh outage schedule**.
4. Натисніть **Run workflow** для першого ручного запуску.
5. Відкрийте журнал запуску. Крок **Fetch and validate public schedule data** має завершитися успішно. Якщо upstream-сторінка змінила HTML-структуру або стала недоступною, скрипт завершується з помилкою й **не замінює останній файл вигаданими даними**.
6. Після успішного запуску перевірте `data/schedule.json` і сторінку сайту.

GitHub Actions запускається за принципом best effort: cron може запізнюватися, і це не гарантія оновлення рівно кожні 10 хвилин. Якщо дані в джерелі не змінилися, коміт не створюється. Коли графік змінюється, workflow оновлює JSON у гілці `main`, і GitHub Pages підхоплює зміни.

## Як користуватися сайтом

1. Натисніть **Додати адресу**.
2. Заповніть населений пункт, вулицю та номер будинку. Назву на кшталт «Дім» або «Робота» можна додати для зручності.
3. Натисніть посилання в формі, щоб перевірити підчергу адреси в оператора. Поверніться на сайт і вкажіть підтверджену підчергу (наприклад, `3.1`).
4. Натисніть **Зберегти адресу**. Надалі ця адреса автоматично залишатиметься у списку на тому самому пристрої та в тому самому браузері.
5. Додайте інші місця за потреби. Перемикайте адреси з карток у блоці «Мої адреси», а дні — вкладками «Сьогодні» та «Завтра».

## Що означають кольори

- Зелений — джерело вказує, що електроенергія є.
- Рожевий — джерело вказує на відключення.
- Жовтий — можливе відключення.
- Сірий — надійних погодинних даних для цього інтервалу немає.

Якщо дата джерела не збігається з поточним днем або даних немає, інтерфейс показує попередження. Це краще, ніж помилково видавати застарілий графік за актуальний.

## Файли проєкту

- `index.html` — структура інтерфейсу.
- `styles.css` — адаптивний дизайн і теми.
- `app.js` — адреси, збереження в браузері, графік і стани даних.
- `data/schedule.json` — дані, які читає сайт.
- `scripts/update_schedule.py` — завантаження й перевірка публічного джерела.
- `.github/workflows/update-schedule.yml` — автоматичний запуск скрипта.

## Локальний перегляд на комп'ютері

Не відкривайте `index.html` подвійним кліком: браузер може заборонити `fetch()` для локального JSON. Відкрийте термінал у папці сайту й запустіть:

```bash
python -m http.server 8000
```

Потім відкрийте <http://localhost:8000>.

## Перевірки та межі гарантій

- Код не потребує npm, компіляції чи сторонніх JS-пакетів.
- `localStorage` прив'язаний до браузера та пристрою. Після очищення даних браузера адреси зникнуть; на іншому телефоні вони автоматично не з'являться.
- Ручна кнопка оновлення перечитує розміщений на GitHub Pages файл. Вона не запускає GitHub Actions і не звертається напряму до upstream-джерела з браузера.
- Залежність від зовнішнього джерела залишається: якщо воно недоступне або змінює структуру сторінки, автоматична синхронізація може зупинитися. Перевіряйте вкладку **Actions**.
- Сайт не гарантує відсутність помилок або безперервність сторонніх сервісів. Для оперативної інформації про електропостачання пріоритет має офіційний оператор.
